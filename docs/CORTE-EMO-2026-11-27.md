# Cruce EverythingMoe · corte 2026-11-27

*34 repositorios medidos contra la API de GitHub el 2026-11-27. Dos de los 36 del cruce no se
pudieron medir y se dice por qué abajo.*

---

## 1 · Por qué este corte va aparte del tablero de 37

EverythingMoe tiene **397 entradas**, pero solo **44 son repositorios de GitHub**; las otras 353 son
sitios web. El tablero del 2026-11-27 mide repositorios con estrellas, licencia, push, release y
checksum. Meter aquí las 353 webs sería cambiar de unidad sin decirlo. Este corte mide **solo
repositorios**, con el mismo método, y va con fecha propia.

De los 44 repositorios del directorio: **8 ya estaban medidos** en el corte anterior y **36 son
nuevos**. Se midieron los 36; **34 respondieron**.

lección más útil de la tanda: el tamaño no protege de la muerte.

## 4 · El checksum, otra vez con la misma vara

Del corte anterior salió una corrección incómoda: llamar «checksum» al `digest` que calcula GitHub
inflaba la cifra. Aquí se aplica la misma separación desde el principio:

| Forma de checksum | Repositorios |
| :--- | ---: |
| Lo **publica** el proyecto (archivo o tabla en las notas) | **2** de 34 · 5,9 % |
| Solo tiene el `digest` que calcula la API | **23** |
| Ni una cosa ni la otra | **9** |

Los dos que publican de verdad: **`ireaderorg/ireader`** y **`senzmaki/senpwai`**. Los demás
dependen de que GitHub calcule el hash al servir el archivo, lo cual sirve para comprobar una
descarga pero no sobrevive a una release editada.

## 5 · Lo que este corte NO afirma

- **No se ejecutó ninguna suite de pruebas.** El entorno tiene ahora JDK 21, Go 1.24 y Android SDK
  base, pero **no tiene .NET, ni Flutter, ni plataformas Android**, y estos 34 son en su mayoría
  Kotlin/Android y Flutter. Se declara igual que en el corte anterior.
- **No se auditó el código** de los 34. Se midió su estado público, que es distinto.
- **Las 353 webs de EverythingMoe no se tocaron.** No son repositorios y no caben en esta tabla.
