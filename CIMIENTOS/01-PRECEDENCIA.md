# 01 · Precedencia

Cuando dos reglas se contradicen, la casa no improvisa: aplica este orden y deja constancia.

## El orden

1. **La verdad del dato** manda sobre la belleza del texto. Si una cifra no se pudo medir, se dice;
   no se redondea para que suene mejor.
2. **La seguridad del lector** manda sobre la exhaustividad. Ante la duda de si un enlace o un
   paquete es legítimo, se publica como hueco o como advertencia.
3. **El Manual V3.0** manda sobre el gusto de quien escribe: cabecera, mapa, «En una página», meme
   del corte, firma y cierre tienen forma fija.
4. **La banda de longitud** manda sobre el impulso de cortar: si falta contenido, se investiga más;
   no se rellena ni se recorta la sustancia.
5. **La longitud manda sobre la prisa.** Una pieza fuera de banda no se publica «porque ya está».
6. **El acta manda sobre el README.** Si el mapa del repositorio y un acta fechada discrepan, gana
   el acta; el README se corrige después.

## Conflictos típicos y su resolución

| Conflicto | Resolución |
|---|---|
| «Queda más elegante decir “la mejor opción”» | Prohibido por el manual: se sustituye por criterio medible |
| «La pieza está en 39.800 y hay que entregar ya» | No se entrega: falta banda. Se añade una sección con contenido nuevo y medido |
| «El dato es viejo pero sirve» | Se publica **con su fecha** y se declara rancio si supera el umbral (180 días) |
| «El repositorio tiene muchas estrellas, seguro está bien» | Las estrellas no son mérito operativo: manda fecha de paquete, licencia y estado |
| «Borramos la pieza vieja y ya» | No: acta → pieza → envío → sello. En ese orden, o las compuertas cantan |
| «El dueño pidió algo que choca con la ley» | Se explica el choque y se ofrece la alternativa legal; la raya legal no se cruza |

## Quién puede cambiar una regla

Solo el dueño, por escrito y con fecha. El cambio se anota en el documento fuente (no en un
comentario suelto) y se refleja en `docs/ERRATA-*.md`. Un agente puede proponer; nunca sustituir.
