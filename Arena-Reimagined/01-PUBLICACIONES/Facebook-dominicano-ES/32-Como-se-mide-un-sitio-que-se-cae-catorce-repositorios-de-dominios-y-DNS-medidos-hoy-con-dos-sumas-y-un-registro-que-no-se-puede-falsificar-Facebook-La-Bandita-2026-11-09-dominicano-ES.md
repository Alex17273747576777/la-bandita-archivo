*📐 El método · registro, DNS y cabecera*

Esto no es teoría: es lo que se hizo para medir ocho dominios en la pieza 36 de esta serie, y cualquiera puede repetirlo.

**Primero, el registro del dominio.** Quién lo tiene y hasta cuándo:

```
curl -s -H "Accept: application/rdap+json" \
  "https://rdap.verisign.com/com/v1/domain/ejemplo.com"
```

Devuelve la fecha de alta, la de vencimiento y el estado. Si el estado dice `client transfer prohibited`, el dominio está **bloqueado para transferencia**, que es lo normal en un dominio activo. Si dice `pending delete` o el registro no existe, el dominio se está cayendo.

**Segundo, el DNS.** Si el dominio apunta a algún sitio:

```
dig +short ejemplo.com A
dig +short ejemplo.com NS
```

Sin respuesta `A`, no hay servidor. Sin `NS`, no hay quién traduzca el nombre.

**Tercero, la cabecera.** Si algo responde:

```
curl -sI https://ejemplo.com
```

Un `200` es un sitio vivo. Un `405` puede ser un servidor que rechaza el método pero existe. Un `000` en curl es que no hubo conexión.

**Las tres cosas juntas son la medición.** Un dominio pagado hasta 2027 que no resuelve es un sitio apagado a propósito, no un sitio muerto: nadie dejó de pagar, alguien dejó de servir. Y esa diferencia es la que ningún artículo te dice.

*❓ Las preguntas del grupo*

**«¿Un dominio pagado puede estar caído?»** Sí, y es lo más común: se sigue pagando por si vuelve, pero el servidor ya no está.

**«¿Y si dice `clientHold`?»** Entonces el registrador lo suspendió. Es distinto de `client transfer prohibited`, que solo bloquea una transferencia. Es un error fácil de cometer y esta serie lo cometió una vez y lo corrigió en público.

**«¿Esto sirve para cualquier dominio?»** Para `.com` y `.net` hay registro público sin llave. Para otros hay que buscar el registro de su país.

**«¿Con qué me quedo?»** Con las tres consultas. Son gratis, no piden cuenta y contestan en un segundo.
